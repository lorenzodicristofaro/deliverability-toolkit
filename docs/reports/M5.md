# M5 — Content analyzer + admin rules: milestone report

Date: 2026-11-10 · Status: **accepted; all seeded content rules disabled by maintainer decision** · `dev` → `qa` after green dev CI

## Acceptance
- "Rules editable without redeploy": `tests/content/test_acceptance_m5.py`. A tenant admin creates a rule, edits its weight and disables it, and each change shows in the next analysis with no restart or re-seed. A global rule from the instance admin reaches two tenants, and tenant rules stay invisible to the other tenant in both directions.
- "Regex timeout enforced": a catastrophic rule gives `timed_out` in `/rules/test`. In a full analysis it gives a rule-level `error`, the overall status is `error`, and the other rules still run. The ReDoS guard is a worker subprocess with an enforced timeout (M5-03).
- Service, REST and CLI JSON are byte-equal, and the UI shows the same status and codes. A recorder on connect, sendto, getaddrinfo and gethostbyname confirms zero network use during content analysis (links are never fetched).
- Custom DNS checks (`dns_exists`, `dns_matches`, `dns_value_range`) run end to end against a fake DNS backend. `http_fetch` is rejected at schema, API and UI, and moves to M7.
- Full suite on PostgreSQL locally: green. ruff, format and mypy are clean.
