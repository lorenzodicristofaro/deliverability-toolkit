# M4 — Original (headers) analyzer: milestone report

Date: 2026-11-07 · Status: **accepted with condition: parser verified against RFC corpus; provider samples pending** · `dev` → `qa` at c2c2733 (dev CI 42378609022 green incl. PostgreSQL)

## Acceptance
- "Sample corpus parsed correctly": `tests/services/test_acceptance_m4.py` runs every MANIFEST sample through the service, `POST /api/v1/message/analyze`, `dtk analyze --format json` and the web UI. Service, REST and CLI JSON are byte-equal (the CLI adds one trailing newline). The UI shows the same finding codes and statuses. Verified samples: plain-rfc, arc-rfc8617 and 6 malformed-* samples. **Unverified** (asserted only as "parsed, sections present"): Gmail, Outlook/M365, SES, SendGrid, MailUp. The maintainer must supply sanitized real `.eml` files (checklist in `tests/fixtures/messages/README.md`).
- Hostile inputs (oversize, NUL, fold bomb, 500+ headers, deep MIME, 10k hops, RFC 2047 junk, bad and zone-less dates) are run through all three surfaces. Results are 413/422/exit 2 or an `error`/`warn` result, never a crash or hang. Sockets are blocked and the DNS fake records zero queries. DB row counts don't change and no content is logged. Denied callers never invoke the analyzer.
- Local suite on `dev`: 8974 passed, 1993 skipped (PostgreSQL parameters run in CI). ruff, format and mypy are clean.

## Notable outcomes
- Offline analyzer: no DNS, no signature verification, nothing stored. Results show what the receiving server *stated*. Authentication-Results are never trusted; `authserv_id` is carried so mixed sources are flagged.
- Parsers with no regex, or with linear and bounded regex: header block, MIME, Received, Authentication-Results, ARC. Each has a seeded fuzz test and a time bound.
- `message.analyze` permission: owner, admin and analyst; never a client viewer.
- Surfaces:
  - REST `POST /api/v1/message/analyze` (raw body, streaming size cap)
  - web `/tools/message` (paste, plus an upload through a static JS file under CSP `script-src 'self'`)
  - CLI `dtk analyze FILE|-` (exit codes 0/1/2/64)
- Docs: `docs/HEADERS.md` (scope, limits table per surface, codes and severities, sample checklist) and `docs/CHECKS.md` (CLI analyze).
- No new dependencies.
