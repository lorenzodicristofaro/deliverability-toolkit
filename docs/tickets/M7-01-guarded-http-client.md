Acceptance criteria:
- One entry point `fetch(url, *, method GET/HEAD, plus POST with a size-capped body for alert webhooks (M7-17; POST never follows redirects by default), headers allowlist, limits) -> FetchResult | typed FetchError`; no other module may import an HTTP library directly (add a test that greps `app/` for direct `httpx`/`requests`/`urllib.request`/`aiohttp` imports outside `app/net/`, with an explicit allowlist for existing legitimate uses if any are found; list them in the PR).
- Scheme allowlist https and http; port allowlist 80 and 443 by default (configurable setting, validated); userinfo in the URL rejected; hostname normalised with IDNA, length/label limits via existing `app/core/domain_names.py` rules; IP-literal hosts are classified directly.
- Resolution through the project resolver (the DNS layer), not the OS resolver; EVERY A/AAAA address is classified with `address_reason`; the request is refused if ANY resolved address is blocked (no "pick the good one"). Blocked ranges include loopback, private, link-local (incl. 169.254.169.254 and the IPv6 metadata/ULA ranges), CGNAT, multicast, reserved, IPv4-mapped/6to4/NAT64 embedding a blocked v4, unspecified. Resolution failure -> typed `dns_error` (never success, never swallowed).
- Connection pinning: the TCP connection goes to the validated IP; TLS SNI and certificate verification use the original hostname; the Host header is the original. A test with a fake resolver that returns a public IP first and a private IP on a second lookup proves no second lookup happens between check and connect (DNS rebinding).
- Redirects: followed manually, cap (default 3, configurable, hard max 5); each hop re-runs the full validation (scheme, port, resolve, classify, pin); an https -> http downgrade is refused; a redirect to a blocked address yields the blocked error with the hop number; relative and malformed Location handled; redirect loop detected.
- Caps: connect timeout, total deadline across redirects, response body size cap enforced while streaming (stop reading, do not buffer first), header size/count cap, decompression-bomb safe (cap applies to decoded bytes; or send no Accept-Encoding and refuse Content-Encoding), no cookies stored, no auth/proxy headers forwarded across origins.
- No proxy leakage: client built with environment proxy support disabled (trust_env off; `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY`, netrc ignored); a test sets those env vars to a canary and proves they are not used.
- Result type carries final URL, status, bounded headers subset, body bytes (capped), `truncated` flag, hop list; errors are a closed enum (`blocked`, `dns_error`, `timeout`, `too_large`, `too_many_redirects`, `scheme_not_allowed`, `port_not_allowed`, `tls_error`, `connect_error`, `protocol_error`). Callers map these to Check `error` status; there is no "not found means ok" path.
- Tests: table-driven, no network (fake resolver + in-process fake transport or loopback server bound only in the test with the policy bypass injected via a test-only seam that is not reachable from settings); cases: every blocked range class, decimal/octal/hex IP spellings, IPv6 zone ids, trailing dot, uppercase, `@` tricks, mixed public+private answers, redirect to metadata IP, rebinding, slow-loris body (deadline), oversize body, endless redirect, proxy env canary.
- ARCHITECTURE.md section 9 rewritten as the decision record (what is blocked, how pinning works, limits table with defaults, the test seam, "SMTP: separate ticket, same policy").
Unverified external facts: none to be asserted about vendors. The default limit values are project choices, not vendor facts; state them as such. Library behaviour (SNI/pinning API of the chosen HTTP library) must be checked against its current documentation by the coder; if the library cannot pin without a custom transport, say so in the PR.
